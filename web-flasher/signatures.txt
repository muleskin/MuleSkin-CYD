# Extra detection rules, delivered to boards without a firmware release.
#
# build_flasher_bins.sh signs this (with OTA_SIGNING_KEY) into
# manifest-signatures.json; boards fetch it during their boot update check
# and use a set only when its SERIAL is newer than theirs and the signature
# is good. Raise SERIAL every time you change the rules.
#
# One rule per line:
#
#   OUI aa:bb:cc TYPE [HIGH|MED|LOW] [Vendor]   an address prefix
#   SSID prefix TYPE [Vendor]                   a WiFi network-name prefix
#   UUID 0xFD84 TYPE [Vendor]                   a 16-bit Bluetooth service UUID   (v3.1.6+)
#   CID 0x0FAB TYPE [Vendor]                    a Bluetooth company ID            (v3.1.6+)
#   NAME prefix TYPE [Vendor]                   a Bluetooth device-name prefix    (v3.1.6+)
#   DROP OUI|SSID|UUID|CID|NAME key             withdraw a rule, built in or not  (v3.1.6+)
#   GRADE aa:bb:cc HIGH|MED|LOW                 re-grade a known address prefix   (v3.1.6+)
#
# TYPE: FLOCK AXON META SKIMMER RAVEN AIRTAG DRONE ALPR CAMERA SAMSUNG_TAG
#       GOOGLE_TAG TILE RING DEAUTH EVIL_TWIN IBEACON HACKER
# Vendor: one word, up to 15 characters. OUI confidence defaults to MED; the
# Bluetooth kinds take their type's own grade, as the built-in ones do.
# Added rules never change what the firmware already knows -- only DROP and
# GRADE do, and that is what they are for: taking back a prefix that turned
# out to be wrong without a release. Older firmware skips the kinds it does
# not know, so a set can use them freely. At most 64 OUI, 32 SSID, 32
# Bluetooth, 32 DROP and 32 GRADE rules; the signed set must stay under
# 2000 bytes.
#
# Examples (not active -- remove the leading # to use):
#   OUI 12:34:56 FLOCK HIGH NewCamCo
#   SSID Spycam- CAMERA SpyCamInc
#   DROP OUI 00:0e:58

# Set 5 (v3.8.0): WatchGuard, DigitalAlly, ShotSpotter, i-PRO, the DJI

# Set 6 (v3.9.0): every other rule of sets 2-4 is built in as well, so the
# set is empty: the notes below say where each one came from. New rules go
# here again, and move into src/signatures.cpp at the next release.
